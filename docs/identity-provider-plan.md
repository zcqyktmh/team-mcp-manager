# 统一登录与身份源规划

## 网站扫码登录（默认入口）

用户可直接在管理器点击「云之家扫码登录」，无需先打开工作台。按[官方扫码登录文档](https://www.yunzhijia.com/opendocs/docs.html#/tutorial/index/qrcode-login)接入：

1. 创建专门的扫码登录应用，将该应用的移动端访问地址设为官方固定值 `https://www.yunzhijia.com/opencloud/openthird/qrlogin`，保存该扫码应用的 AppID 与 AppSecret。
2. 管理器选择「网站扫码登录」，填写扫码应用的 AppID、AppSecret、企业 eid、首位管理员资料和企业成员 openid。管理器回调地址使用公司 HTTPS 域名下 `/auth/cloud-home/entry`，与上一步的云之家固定地址不同。
3. 员工点击登录，服务端生成五分钟有效的随机 state，并用 HttpOnly、SameSite=Lax Cookie 绑定发起浏览器，跳转官方 `https://www.yunzhijia.com/opencloud/openthird/qrconnet`。参数为 appid、appName、redirect_uri、state，使用 URL 编码，不在其中传递密钥。
4. 官方页面显示二维码，员工用云之家 App 扫码确认。扫码账号所在团队必须开通该扫码应用。被扫的电脑浏览器回到管理器回调，携带 ticket 与 state。
5. 校验 state 与浏览器 Cookie、有效期和一次性状态，然后复用下方服务端 ticket 交换、企业/appid/openid 校验、预绑定账号查询、员工确认和会话建立流程。

不生成演示二维码，不使用云之家官网的私有登录接口。当前未找到公开的第三方直接验证云之家用户名密码的正式接入协议，因此不在管理器收集云之家密码；如企业另有正式 SSO，需按企业提供的协议另行接入。

## 云之家工作台轻应用接入（可选）

2026-10-22 核对官方公开文档后，确认轻应用采用 ticket 免登；网站入口进一步按官方扫码文档实现 QR 回调。此前的通用 OAuth 授权码实现保留为可选模式；只有企业另外提供对应协议时才使用，不能把它视为云之家标准流程。

1. 企业管理员在云之家 Web 端「管理中心 → 轻应用管理」注册企业自建轻应用，保管 AppID 与 AppSecret。联调期间仅向测试人员开放可见范围。
2. 在管理器后台「集成登录」选择云之家，填写 AppID、AppSecret、企业团队 eid，以及公司 HTTPS 域名下的 `/auth/cloud-home/entry`。把相同 URL 配为轻应用移动/Web/桌面端访问地址。
3. 企业管理员取得首位管理员在该企业的 openid，核验手机号，并填写其管理器账号、姓名、手机号与 openid。其他员工先登记管理器账号、手机号及用户组，再通过「绑定云之家」预绑定企业 eid 和成员 openid。
4. 保存后可点击「检查已保存的应用凭据」。这只检查能否取得 app 级令牌，不代表 ticket、企业身份或手机号已验证。
5. 勾选启用，保存并重启管理器。员工从云之家工作台打开轻应用，云之家在访问地址附加一次性 ticket。
6. 管理器服务端以 JSON POST 请求应用令牌接口，参数为 `appId`、`secret`、13 位毫秒 `timestamp`、`scope: app`；按返回有效期缓存应用令牌。
7. 服务端 JSON POST 身份接口，查询参数携带 `accessToken`，正文为 `appid`、`ticket`、`disposable: true`。严格检查成功标识、返回 appid、企业 eid 和成员 openid。
8. 清理浏览器地址中的 ticket，将已验证身份暂存最多五分钟。员工确认当前身份后，系统查找已预绑定账号；未绑定、手机号未登记、企业或应用不符均拒绝登录。首次管理员仅按配置中精确的企业 eid 与 openid 引导初始化，不按姓名自动提权。
9. 建立签名会话 Cookie（HttpOnly、SameSite=Lax；HTTPS 配置启用 Secure）。默认会话为服务端内存存储，12 小时滑动有效期，重启后重新登录。

选择工作台免登模式时，需从工作台进入；选择网站扫码模式时，直接在管理器发起扫码。两者最终都验证一次性 ticket。Web/桌面客户端入口、二维码有效期及嵌入式浏览器 Cookie 行为仍需企业真实联调。

## 手机号和身份边界

官方身份结果包含企业 eid、企业内成员 openid、用户名及用户级 userid 等，**不保证包含手机号**。deviceId 是设备标识，用户名是姓名，都不能作为手机号或可靠绑定条件。当前方案由管理员先核验手机号，再预绑定 eid + openid；不宣称已完成短信验证或从云之家自动验证手机号。若企业要求平台返回手机号自动校验，需要取得对应人员接口及字段权限后另行接入。

云之家密码和登录验证由云之家处理，管理器不收集密码。密码复杂度、过期、多因素的实际可用性和配置位置需由企业云之家管理员确认；管理器不能通过 ticket 接口修改这些策略。账号换绑和已绑定手机号变更需要重新核验，当前禁止直接覆盖。

## 服务端配置与运行

云之家配置保存到 `data/auth-settings.json`；其他平台分别保存到 `data/auth-provider-<平台>.json`。文件含应用密钥，需限制服务账号文件权限并保护备份，当前未接入专用密钥库。浏览器不回显密钥；留空保留已有值，提交后清空输入。支持先保存草稿，重启后生效。文件优先于 `.env` / `data/auth.env`；旧配置没有 loginMode 时按原通用 OAuth 模式保留，迁移到 ticket 需明确选择并补齐 eid/openid。

启用企业登录但配置不完整时，受保护 API 拒绝请求，不自动退回匿名管理。后台配置、凭据检查和身份预绑定仅平台管理员可操作。日志不记录密钥、应用令牌、ticket、请求正文或 URL 查询参数。MCP 客户端 OAuth 服务尚未完成，启用企业登录时拒绝 `/mcp` 请求。

可通过 `MCP_MANAGER_DATA_DIR` 设置服务数据目录；本机开发默认使用项目 data，打包版默认使用对应系统的应用数据目录。

## 多身份源

平台下拉用于切换编辑对象。多个平台配置独立保存，不会互相覆盖；当前仅云之家实现运行时适配。企业微信、钉钉、飞书、QQ、微信目前只能保存通用接入资料草稿，服务端禁止启用。社交账号需具备公司认可且可验证的企业身份映射，不按昵称或头像关联。

后续补齐各平台专有字段、登录适配、解绑审核、会话撤销、员工离职停用、共享会话存储和 MCP 客户端 OAuth 授权网关。

### 首位管理员扫码初始化

在服务器本机打开集成登录配置页，选择网站扫码登录，填写应用资料、管理员账号、姓名和已核验手机号。openid 可以留空，先保持未启用并保存草稿。点击「准备扫码」，打开官方扫码页；完成后回原配置页点击「查看扫码结果」，核对企业、姓名、成员标识及目标账号，再点击确认绑定。系统只保存已在服务端验证的 openid；不会在扫码回调时自动建立管理员会话。最后勾选启用、保存并重启。

初始化使用当前本机浏览器的 `/auth/cloud-home/entry` 作为回调，必须在同一浏览器完成，五分钟内有效。电脑浏览器接收回调，手机只负责扫码。正式登录仍使用配置的回调地址。初始化接口拒绝远程主机、转发请求和跨站提交；已有管理员标识或启用登录后关闭。页面中登记的手机号仍需人工核验，不代表云之家验证过手机号。此功能目前需在服务器本机浏览器操作，不支持通过反向代理远程初始化。
