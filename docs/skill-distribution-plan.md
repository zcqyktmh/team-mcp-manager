# Team Skill 上传、审核与同步规划

## 目标

员工可以从 AI 工具发起 Skill 上架申请；管理员通过网页检查内容并审批；批准后的版本进入公司 Skill 目录，员工再按权限同步到自己的 AI 工具。所有环节留有版本、哈希和操作审计。

Skill 是给 AI 使用的说明和配套文件，通常包括 `SKILL.md`、参考资料、模板、图片或脚本。它不等同于 MCP 服务，也不应自动获得数据库、金蝶、文件服务器等 MCP 工具权限。MCP 工具调用授权仍由 MCP 管理器单独执行。

## 本机原型已实现

- 网页 ZIP 上传、指定演示审核人、申请记录与审核操作。
- 上传时校验 ZIP 路径、文件数量/大小/类型、Skill frontmatter 和疑似凭据；脚本与主动内容会标记给审核人。
- 通过后按 Skill 标识和版本保留原始 ZIP，形成可下载的版本目录；较高版本发布后保留历史版本。
- 管理器不会执行 Skill 文件。当前没有云之家登录，也没有按真实员工身份实施审核或下载授权；上传包检查不等于恶意软件检测。
- 仍待实现：AI 工具发起 Skill 包申请、MCP Skills 扩展读取、客户端同步器、用户组下载隔离、签名、撤回与回滚。

## 产品边界与客户端兼容

- MCP Skills 扩展定义了 `skills/list`、`skills/get`，并通过 `resources/read` 提供 Skill 文件；可作为服务器端分发接口。
- 不假定 Codex、WorkBuddy 或其他 AI 客户端都已支持该扩展。管理器维护客户端能力表，并分别验证发现、读取和更新能力。
- 兼容性兜底是提供用户侧“Skill 同步器”：从已授权目录下载已批准版本到用户选择的 Skill 文件夹。同步器不安装或启动 MCP 服务，也不执行 Skill 中的脚本。
- AI 工具里的上传 MCP 工具提交申请信息和来源地址；较大的 ZIP/目录包通过管理网页或 Git 导入，不通过 MCP 参数传输大段 base64 文件。

## 角色与权限

| 角色 | 能做什么 |
| --- | --- |
| 申请人 | 上传新 Skill 或提交新版本；查看本人申请状态和审核意见 |
| 审核人 | 查看固定版本、差异和扫描结果；通过、驳回或要求修改 |
| 发布管理员 | 管理目录元数据、分配适用用户组、撤回版本 |
| 员工 | 查看获准目录、订阅 Skill、拉取或回滚到可用版本 |
| 安全管理员 | 配置文件类型、脚本政策、扫描规则和客户端兼容策略 |

角色身份必须由云之家登录态映射，不能信任 AI 工具请求里自报的账号。高风险脚本类 Skill 可要求双人审核。

## 上传与审核流程

1. 申请人从 AI 工具调用 `submit_skill_publication`，提交 Skill 名称、用途、目标用户组、版本说明和附件/导入来源；服务器返回申请编号。
2. 管理页面上传 ZIP、选取工作区文件夹，或从允许的 Git 仓库与指定 commit 导入。禁止任意 URL 直连导入，避免 SSRF。
3. 服务器解包到隔离暂存区，检查路径穿越、压缩炸弹、符号链接、文件大小/数量、重复路径、秘密信息和不允许的可执行文件。
4. 校验 Skill 目录结构、`SKILL.md` frontmatter、名称、描述、文件清单和引用路径；生成每个文件 SHA-256 与整体版本摘要。
5. 固定待审内容快照，记录扫描结果、来源 commit、上传人和摘要。审核只针对这个不可变快照，不能在审批后替换文件。
6. 指定审核人查看文件树、文本差异、脚本、权限声明和扫描结果；通过、驳回并填写意见，或要求申请人修改后重新提交。
7. 通过后创建不可变版本，进入目录；发布不会执行文件里的脚本。

## MCP 管理工具

首期提供面向 AI 客户端的申请和目录工具：

- `submit_skill_publication`: 创建申请、声明来源与目标用户组。
- `get_skill_publication_status`: 查询申请状态和审核意见。
- `list_available_skills`: 查询当前身份可见的 Skill 与已批准版本。
- `get_skill_version`: 读取版本清单、摘要、变更说明和文件下载引用。
- `request_skill_sync`: 请求将指定版本同步到当前账号已登记的客户端。

若客户端支持 MCP Skills 扩展，再提供 `skills/list` 和 `skills/get`。MCP 工具的用户身份从已验证的 OAuth/云之家会话获得；工具参数里的账号只允许作为展示字段，不参与授权。

## 同步与拉取

- 用户可按组订阅 Skill；同步前显示版本、变更摘要、来源和目标客户端。
- 默认只自动拉取管理员批准且已订阅的稳定版本；测试版或高风险 Skill 需用户确认。
- 同步器先下载到临时目录，校验签名/摘要和文件清单，再原子替换目标版本；失败时保留原版本。
- 每个客户端独立记录安装位置、当前版本、上次同步时间和结果。首次同步由用户选择客户端与目录，不扫描或覆盖其他个人文件夹。
- 提供“检查更新、立即同步、暂停自动同步、回滚到上一批准版本、卸载 Skill”操作。
- 管理员撤回版本后阻止新拉取并通知已安装用户；是否远程删除本地 Skill 需另设策略，默认不静默删除用户文件。

## 管理界面

1. **Skill 目录**：搜索、分类、适用用户组、维护人、当前稳定版本、风险级别、客户端兼容状态。
2. **上传/导入**：ZIP/目录上传、Git 来源、版本说明、目标范围、草稿预览。
3. **审核工作台**：文件树、差异查看、扫描报告、审核意见、双人审批记录。
4. **版本页**：不可变版本列表、哈希、来源、变更说明、发布时间、回滚/撤回。
5. **用户同步**：已订阅项目、客户端状态、安装版本、同步结果和失败重试。
6. **策略与审计**：上传/审核/发布/下载/同步/撤回记录；可按人员、Skill、版本和时间筛选。

## 建议的数据对象

- `skills`: 稳定标识、名称、描述、分类、维护人、风险级别、生命周期状态。
- `skill_versions`: 版本号、不可变存储位置、清单、整体哈希、来源、扫描结果、审核记录、发布时间。
- `skill_submissions`: 申请人、来源、目标范围、待审版本快照、状态、指定审核人、意见和时间。
- `skill_files`: 版本 ID、相对路径、媒体类型、大小、SHA-256。
- `skill_subscriptions`: 用户/组、Skill、客户端和自动同步设置。
- `skill_sync_jobs`: 用户、客户端、版本、状态、失败信息和时间。
- `skill_audit_events`: 操作人、动作、对象、版本、来源地址、结果。

## 分阶段交付

### 阶段 1：可审核的目录 MVP

- 网页上传 ZIP、自动检查结构与文件安全、审核队列、通过后建立不可变版本。
- AI 工具创建申请、查询状态；申请人账号和审核人身份使用登录态。
- 目录可搜索、查看详情和下载已批准包；带全量审计。
- 不做客户端自动安装，不运行任何包内脚本。

### 阶段 2：客户端同步

- 实现用户侧同步器，先覆盖 Codex；与 WorkBuddy 等客户端逐一验证目录发现和热更新能力。
- 支持按用户组授权、订阅、哈希校验、原子升级、失败保留和回滚。
- 若客户端支持 MCP Skills 扩展，增加远程只读发现/读取；不支持时使用同步器。

### 阶段 3：Git 协作和企业治理

- Git 仓库/分支/commit 导入、定时检查更新、差异审核和人工发布。
- 增加测试/稳定渠道、签名、双人审批、撤回通知、使用统计和客户端合规报告。
- 根据试点需求再评估自动更新；高风险 Skill 保持人工确认。

## MVP 验收标准

- 非管理员不能审核或发布；身份由云之家认证，不采用请求自报账号。
- 上传的路径穿越、超限包、坏格式和秘密扫描命中项会阻止进入待发布版本。
- 审核人看到的文件摘要与最终发布版本完全一致；审批后内容不可变。
- 普通员工只能查阅和拉取授权用户组的已批准版本。
- 客户端同步会校验摘要，失败不会损坏旧版本；所有状态变化可审计。
- 撤回后目录不再允许新安装，并保留历史审核与同步记录。
