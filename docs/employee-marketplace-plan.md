# 员工工作台、发布与外部市场

## 已确认的产品规则

- 每位员工通过企业账号登录，拥有自己的工作台、提交记录、使用申请和已授权资源。
- 员工可提交 MCP 与 Skill 的新资源和新版本，也可由已认证的 AI 工具代为提交；申请人从登录身份取得。
- 发布审核与使用申请分别审批。资源作者身份不自动获得平台管理员或服务器部署权限。
- 管理员公开发布的资源对全员可见、可获取；受限资源的详情、文件、下载及同步入口必须在服务端检查授权。
- 受限资源提供申请入口；管理员可设置申请入口公开或仅对指定用户组开放。未获批员工只能看到允许公开的申请摘要。
- 员工申请使用受限 MCP 或 Skill，填写工作用途。管理员通过或驳回并说明原因；员工可查看进度。
- MCP 的目录访问授权、工具操作授权、目标系统员工身份分开记录。批准查看 MCP 不代表批准写入、删除或读取任意业务数据。
- Skill 使用审批通过后可下载或同步批准版本；Skill 本身不附带 MCP 调用权限。

## 员工提交与服务器自助部署

MCP：草稿 → 提交固定版本 → 管理员审核 → 允许部署 → 员工点击部署到公司服务器 → 健康检查 → 管理员发布到公司市场。

Skill：上传固定版本 → 内容检查 → 管理员审核 → 发布到公司市场 → 员工按权限下载或同步。

MCP 支持两种提交方式：登记已有远程服务；提交允许部署的镜像或源码版本。已有远程服务可跳过部署，仍需审核并登记工具清单。

审核固定镜像摘要或源码 commit、工具定义、运行参数、访问范围和版本内容。版本或部署权限发生变化需重新审核。员工只能部署已批准版本到管理员指定的运行环境，不能提交任意服务器命令。

部署执行器提供排队、部署中、成功、失败、回滚状态，以及脱敏日志、启动检查、停止和上一批准版本回滚。管理员配置运行模板、网络、目录挂载、资源配额和密钥引用。系统保存部署实例与发布版本的对应关系。

平台运行凭据与员工业务凭据分别管理。MCP 以隔离服务运行；访问金蝶、数据库、文件服务器等业务系统时仍使用员工绑定的个人身份与授权，不能把部署人凭据共享给其他员工。

## 统一使用申请

申请记录包含资源类型、资源 ID、申请人、用途、申请范围、提交时间、审核人、意见和有效期。MCP 工具权限申请额外记录工具与资源范围。

审批通过创建独立授权记录。授权支持撤销与到期失效；下载、资源详情、同步和调用均重新检查当前授权。资源撤回后停止新下载与新连接。已下载的文件无法通过撤销授权自动收回。

## 外部 Skill / MCP 市场

管理员维护多个来源连接器，逐步支持允许的 Git 仓库、镜像仓库以及外部 Skill/MCP 市场。每个连接器独立保存地址、认证引用和更新策略。

流程：选择来源 → 搜索或填写资源链接 → 拉取指定版本到暂存区 → 展示来源、许可证、版本、摘要、依赖和权限 → 内部审核 → 部署或发布。

外部来源更新只生成待审版本，不覆盖已批准版本，不直接部署。保留上游资源标识、commit/镜像摘要、来源地址与内部版本，支持检查更新、差异预览、停止同步和版本回滚。连接器逐个适配，不假设所有市场具有统一接口。

## 页面入口

- 员工工作台：公司市场、我的资源、我的提交、我的使用申请、我的部署。
- 提交资源：MCP / Skill 选择、来源或上传、版本说明、权限声明与发布范围。
- 管理后台：发布审核、使用申请审核、运行环境、部署任务、来源市场、版本与授权管理。
- 输入和审核意见使用弹窗卡片表单。

## 实施顺序与当前边界

1. 完成员工提交入口，并统一 MCP / Skill 的个人申请列表与登录身份校验。
2. 完成受限 Skill 使用申请、下载授权；补齐 MCP 的撤权、有效期与完整授权检查。
3. 实现服务器部署执行器与审批后自助部署，再接入远程 MCP 网关的工具调用授权。
4. 接入首个外部来源，完成固定版本导入与内部审核，再逐个扩展市场连接器。

1.0.0 已实现员工 MCP / Skill 提交与个人记录、受限 Skill 使用审批与版本下载隔离，以及个人令牌 MCP 网关的工具鉴权。服务器自助部署、外部市场连接器、授权有效期和客户端自动同步仍为规划。具体可运行范围见 README 和员工网关说明。
